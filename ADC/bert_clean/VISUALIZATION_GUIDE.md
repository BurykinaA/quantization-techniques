## 🔍 Детальное Описание Каждого Графика

### **ROW 1: Quantization Pipeline (Входы)**

#### 1️⃣ **X_raw** (синий, левый верхний)
**Что показывает:** Распределение RAW (float32) входных активаций

**На вашем графике:**
- Range: [-2.514, 1.587]
- Распределение близко к нормальному, центрировано около 0
- Это выход LayerNorm или предыдущего слоя BERT

**Что смотреть:**
- ✅ Если центрировано около 0 → хорошо для signed quantization
- ⚠️ Если смещено в положительную область → может быть лучше unsigned
- ⚠️ Outliers (очень редкие большие значения) → могут испортить scale

---

#### 2️⃣ **X_codes** (голубой)
**Что показывает:** ЦЕЛОЧИСЛЕННЫЕ коды активаций после квантования

**Формула:** 
```python
code_x = round(X_raw / scale_x)  # для symmetric
code_x = clamp(code_x, qmin, qmax)  # [-128, 127] для 8-bit signed
```

**На вашем графике:**
- scale: 0.067573
- Range: примерно [-40, +20]
- Видно, что используется только часть диапазона [-128, 127]

**Что смотреть:**
- ✅ Если используется весь диапазон [-128, 127] → хорошо, не теряем precision
- ⚠️ Если узкое распределение [-10, +10] → плохо, недоиспользуем биты
- **На вашем графике:** используется диапазон ~60 из 256 уровней → можно улучшить!

**Как улучшить:**
- Уменьшить `scale_x` → коды станут больше → лучше используем range

---

#### 3️⃣ **W_raw** (зеленый)
**Что показывает:** Распределение RAW весов слоя

**На вашем графике:**
- Range: [-0.167, 0.156]
- Симметричное распределение около 0
- Типичное для BERT после fine-tuning

**Что смотреть:**
- ✅ Если симметрично → symmetric quantization правильный выбор
- ⚠️ Если много outliers → percentile calibration поможет
- 📊 Форма распределения влияет на MSE квантования

---

#### 4️⃣ **W_codes** (светло-зеленый, правый верхний)
**Что показывает:** ЦЕЛОЧИСЛЕННЫЕ коды весов (per-channel quantization)

**Формула:**
```python
code_w[i] = round(W_raw[i] / scale_w[i])  # per-channel
code_w = clamp(code_w, -128, 127)  # для 8-bit symmetric
```

**На вашем графике:**
- scale range: [0.000383, 0.003820]  # per-channel scales
- Codes распределены в диапазоне [-100, +100]
- Хорошее использование range!

**Что смотреть:**
- ✅ Если полный range [-128, 127] → отлично!
- ⚠️ Если узкое → можно уменьшить per-channel scales
- **На вашем графике:** хорошо используется диапазон ✅

### **ROW 2: ADC Pipeline (ГЛАВНОЕ!)**

#### 5️⃣ **BEFORE ADC (Y_int)** (оранжевый, левый нижний) ⚡ **KEY PLOT**

**Что показывает:** Выход integer matrix multiply **ДО квантования ADC**

**Формула:**
```python
Y_int = code_x @ code_w  # Integer матричное умножение
```

**На вашем графике:**
- Range: [-19780.0, 13536.0]
- **Красные линии:** ADC boundaries
  - ADC min = -774192.0
  - ADC max = 768143.6
- **ПРОБЛЕМА:** Значения Y_int намного меньше ADC range!

**Критический анализ вашего графика:**
```
Y_int range:     [-19780, 13536]   ← фактические значения
ADC range:       [-774192, 768143] ← доступный диапазон ADC
Δ = 6048.375                       ← квантизационный шаг

Использование ADC range: ~2-3% (!!)
```

**ЭТО ПЛОХО!** ❌ 

**Почему это проблема:**
- ADC имеет фиксированный range [-128*Δ, 127*Δ]
- Ваши Y_int значения используют только ~2-3% этого range
- Значит, вы используете только ~2-3% из 256 ADC levels
- Эффективно у вас ~6-bit ADC вместо 8-bit!

**Как должно быть:**
- ✅ Y_int должен занимать 70-90% ADC range
- ✅ Красные линии должны быть близко к краям распределения
- ✅ Небольшой запас (5-10%) для избежания clipping

**Что делать:**
1. **Уменьшить activation scales** → code_x станет больше
2. **Уменьшить weight scales** → code_w станет больше  
3. **Результат:** Y_int = code_x @ code_w станет больше
4. **Цель:** Заполнить ADC range на 70-90%

---

#### 6️⃣ **ADC codes** (красный, центр нижний) 🎯 **КРИТИЧЕСКИЙ ИНДИКАТОР**

**Что показывает:** Квантованные ADC уровни

**Формула:**
```python
adc_codes = round(Y_int / Δ)
adc_codes = clamp(adc_codes, na=-128, pa=127)  # для 8-bit ADC
```

**На вашем графике:**
- Δ = 6048.375
- Codes сконцентрированы в узком диапазоне [-3, +2]
- na = -128, pa = 127 (показаны красными линиями)

**КРИТИЧЕСКАЯ ПРОБЛЕМА:**
```
ADC range доступен: [-128, 127]   (256 уровней)
Фактически используется: [-3, +2]  (~5 уровней)

Эффективное разрешение: log2(5) ≈ 2.3 бита вместо 8 бит!!
```

**Идеально должно быть:**
- ✅ ADC codes должны занимать диапазон примерно [-100, +100]
- ✅ Использовать ~200+ из 256 уровней
- ✅ Красные линии (na/pa) должны быть на краях, но не слишком далеко

**На вашем графике:** Очень плохое использование ADC! ❌

---

#### 7️⃣ **AFTER ADC** (фиолетовый)

**Что показывает:** Выход после квантования ADC

**Формула:**

**На вашем графике:**
- Range: [-18145.1, 12096.8]

**Что смотреть:**

- ⚠️ Если сильно отличается → большая ошибка квантования

**На вашем графике:**

## 🔧 Диагностика Вашего Случая

### **Проблема: Недоиспользование ADC Range**

**Почему это происходит:**

1. **Слишком большие scales:**
   ```
   scale_x = 0.067573    ← возможно слишком большой
   scale_w = [0.000383, 0.003820]  ← OK
   ```

2. **Результат:**
   ```
   code_x = X_raw / 0.067573 → небольшие коды [-40, +20]
   code_w → OK
   Y_int = code_x @ code_w → маленький результат
   ```

3. **ADC получает маленькие значения:**
   ```
   Y_int = [-19780, 13536]
   Δ = 6048.375
   adc_codes = Y_int / Δ = [-3, +2]  ← ОЧЕНЬ мало!
   ```

### **Решение:**

#### **Вариант 1: Уменьшить scale_x**
```python
# Вместо scale_x = 0.067573
scale_x = 0.067573 / 10 = 0.0067573

# Результат:
code_x ∈ [-400, +200]  # в 10 раз больше
Y_int ∈ [-197800, 135360]  # в 10 раз больше
adc_codes ∈ [-30, +20]  # используем больше ADC levels!
```

#### **Вариант 2: Уменьшить Δ (hardware parameter k)**
```python
# Equation (3): Δ = 2M(2^bx - 1)(2^(bw-1) - 1) / (2^ba × k)
# Увеличить k: 4 → 8 → 16

k=4:  Δ = 6048.375  ← текущее
k=8:  Δ = 3024.188  ← в 2 раза меньше
k=16: Δ = 1512.094  ← в 4 раза меньше

# При k=16:
adc_codes = Y_int / 1512.094 ∈ [-13, +9]  # лучше!
```

**НО:** k — это hardware параметр, его нельзя менять post-hoc!

#### **Вариант 3: Лучшая калибровка scales** ⭐ **RECOMMENDED**

Ваш calibrator должен:
```python
# Goal: Make Y_int fill 70-90% of ADC range
target_y_int = 0.8 * pa * delta  # 80% of max ADC range

# Adjust scales to achieve this:
optimal_scale_x = scale_x * (current_y_int_max / target_y_int)
```
